Mantenimiento web reactivo o preventivo: cuándo basta con arreglar y cuándo conviene revisar

Qué cubre cada enfoque, qué incidencias detecta antes cada uno y cómo decidir cuál necesita tu web.

Equipo web y software de ADQA 4 min de lectura

  1. Inicio
  2. Respuestas
  3. Web y software
  4. Mantenimiento web reactivo o preventivo: cuándo basta con arreglar y cuándo conviene revisar
La respuesta corta

El mantenimiento web reactivo interviene cuando algo ya ha fallado: una caída, un formulario que no envía o un plugin que deja de funcionar. El preventivo revisa la web de forma periódica: actualizaciones, copias, certificado y formularios. Así detecta esos problemas antes de que los note un visitante. El reactivo puede bastar en webs informativas sencillas. Cuando la web genera contactos o ventas, el preventivo suele compensar.

Tu web puede pasar meses sin dar problemas y, un lunes, dejar de enviar el formulario de contacto. Hay dos maneras de prepararte para ese día. Una es arreglar el fallo cuando aparece. La otra, revisar la web con un calendario para encontrarlo antes.

Las dos tienen sentido en algún momento. Lo que las separa es quién detecta el problema y con cuánto margen se resuelve. ¿Lo ve la persona que cuida la web o un cliente que no consigue escribirte?

Lo que el mantenimiento reactivo hace bien

Para algunas webs es una opción razonable, al menos durante un tiempo:

  • Sin cuota fija. Solo se paga cuando hay que intervenir.
  • Sin compromiso continuo. Se encarga de forma puntual, cuando aparece el problema.
  • Suficiente en webs sencillas: informativas, que cambian poco y no generan contactos ni ventas.

Su límite es el momento en que se actúa. El aviso suele llegar de fuera. Puede ser un navegador que muestra un certificado caducado o un correo del proveedor de alojamiento. También puede ser un cliente que te llama para preguntar si recibiste su mensaje de la semana pasada. Así descubres que el formulario lleva días sin enviar nada. A partir de ahí, todo se hace con prisa.

Lo que aporta el mantenimiento preventivo

Un mantenimiento preventivo no elimina los imprevistos. Cambia cuándo aparecen y cómo se resuelven:

  • Detección en la revisión, no en la queja. Un plugin incompatible, un certificado a punto de caducar o una copia incompleta salen en la revisión programada.
  • Actualizaciones al día y probadas, en lugar de acumularse durante meses. Cuantas más se juntan, más difícil es aplicarlas sin conflictos. El método paso a paso está en actualizar WordPress tú mismo o con mantenimiento profesional.
  • Copias que se sabe que funcionan. Se guardan en otro sitio y de vez en cuando se prueba a recuperarlas. Así puedes volver atrás con confianza.
  • Menos urgencias. La mayoría de incidencias se resuelven en horario de trabajo y con calma, no con la web caída.

Al pasar de un enfoque a otro, lo habitual no es que dejen de pasar cosas. Es que dejan de ser urgencias. El certificado se renueva un martes cualquiera, no con el teléfono sonando.

Cinco incidencias habituales, vistas desde cada enfoque

Ninguna de estas situaciones es rara ni grave por sí sola. La tabla te muestra cómo se descubre cada una según el enfoque.

Incidencia Con mantenimiento reactivo Con mantenimiento preventivo
Certificado SSL a punto de caducar Lo descubre el navegador del visitante Se renueva antes de la fecha
Plugin con un fallo de seguridad ya publicado Se corrige si alguien se da cuenta Se actualiza en la revisión
Copia de seguridad que no se completa Se descubre al intentar restaurar Se detecta al comprobar las copias
Formulario que deja de enviar Se nota cuando faltan contactos Se ve en la prueba de formularios
Web cada vez más lenta Se percibe cuando ya molesta Se mide y se corrige por partes

Fíjate en la columna del enfoque reactivo: en casi todas las filas te enteras tarde. Un plugin de seguridad ayuda con parte de estos problemas. Pero por sí solo no aplica las actualizaciones con criterio. Tampoco comprueba que las copias se puedan recuperar ni prueba los formularios. Lo que aporta cada pieza se compara en plugin de seguridad o mantenimiento web gestionado.

Cómo decidirlo

Criterio Mantenimiento reactivo Mantenimiento preventivo
Coste mientras no hay incidencias Ninguno Cuota periódica
Quién detecta el problema Un visitante, el navegador o el alojamiento La revisión programada
Momento de la intervención Con la web ya afectada Antes de que afecte, en la mayoría de casos
Actualizaciones Se acumulan Al día y probadas
Copias de seguridad comprobadas Si alguien se ocupa De forma sistemática
Tipo de web adecuado Informativa, sencilla y con poco tráfico Web que genera contactos, reservas o ventas

Para decidir rápido:

  • Mantenimiento reactivo si tu web es informativa, cambia poco y un día de caída no afecta al negocio.
  • Mantenimiento preventivo si tu web genera contactos, reservas o ventas, o tiene formularios y áreas privadas de uso diario.
  • Un modelo mixto al principio, con revisiones básicas de copias y actualizaciones. Luego las amplías a medida que la web gana peso en tu negocio.

Quién hace esas revisiones, tu equipo o un servicio externo, es otra decisión. Se analiza en mantenimiento web propio o externalizado. La misma lógica de revisar antes de que algo falle sirve para tus otros equipos y sistemas. La verás aplicada en soporte IT reactivo o proactivo.

Preguntas frecuentes

Para el manager

¿El mantenimiento preventivo evita todos los problemas?

No, ningún mantenimiento lo hace. Lo que cambia es que la mayoría de incidencias se detectan en una revisión programada. Se resuelven antes de que las note un visitante. Las que llegan a producirse se atienden con la web documentada y con copias de seguridad comprobadas.

¿Cómo se comparan los costes de los dos enfoques?

El reactivo no tiene cuota fija. Cada intervención se paga cuando ocurre y suele hacerse con prisa. El preventivo tiene una cuota periódica que cubre las revisiones. Para compararlos, suma también el tiempo interno que dedicas a cada incidencia. Ten en cuenta, además, el papel de la web en la captación de clientes.

¿Cuándo conviene pasar del mantenimiento reactivo al preventivo?

Cuando tu web empieza a generar contactos, reservas o ventas de forma regular. También cuando tiene formularios o áreas privadas que se usan a diario. Y cuando en tu empresa nadie sabe qué versiones hay instaladas ni de cuándo es la última copia.

Para el responsable técnico

¿Qué revisa un mantenimiento preventivo de forma periódica?

Se revisan las actualizaciones del núcleo, la plantilla y los plugins. Se comprueba el estado de las copias de seguridad, con una restauración de prueba cada cierto tiempo. Se vigila la caducidad del certificado SSL y del dominio. Y se miden los tiempos de carga y se prueban los formularios y las funciones críticas.

¿Con qué frecuencia se hacen esas revisiones?

Depende de cuánto cambie la web y de su peso en el negocio. Como referencia, las copias suelen ser diarias en webs con actividad. Las actualizaciones se revisan cada pocas semanas. La comprobación completa se hace de forma periódica, a menudo mensual. Y se suman avisos automáticos si la web deja de responder.

¿Cómo se actúa ante una incidencia grave si ya hay mantenimiento preventivo?

Se parte de una web documentada. Hay un inventario de versiones y extensiones, y la última copia ya está comprobada. Con eso se aísla el problema y se restaura si hace falta. Después se corrige la causa sin reconstruir nada desde cero.
