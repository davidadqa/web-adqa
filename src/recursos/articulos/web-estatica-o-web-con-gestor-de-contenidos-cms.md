Cambiar un texto en una web estática significa, casi siempre, pedírselo a quien la programó. En una web con gestor de contenidos, basta con entrar, editar y publicar.

Parece una diferencia pequeña. Se hace grande cuando se multiplica por todas las veces que una empresa necesita actualizar algo a lo largo del año.

## Qué es cada una

Una **web estática** se compone de páginas ya construidas que el servidor entrega tal cual, sin consultar una base de datos. Para cambiarlas hay que editar los archivos y volver a publicarlos.

Una **web con gestor de contenidos (CMS)** guarda los textos y las imágenes en una base de datos y monta las páginas a partir de ellos. Incluye un panel de administración desde el que cualquier persona autorizada puede editar sin tocar el código. WordPress es el más conocido, aunque hay otros.

Ninguna de las dos condiciona el diseño: tanto una web estática como una con CMS pueden partir de una plantilla o hacerse a medida, otra decisión que se explica en [web a medida o plantilla](/recursos/web-a-medida-o-plantilla/).

## Lo que una web estática hace mejor

Para determinados casos, sigue siendo la opción más sólida:

- **Velocidad de carga.** Sin base de datos ni procesos en el servidor, no hay nada que calcular en cada visita, así que las páginas cargan rápido de forma natural.
- **Menor superficie de ataque.** No hay un panel de acceso público ni extensiones que actualizar.
- **Mantenimiento técnico mínimo**, sin actualizaciones periódicas del núcleo ni de complementos.

Funciona bien en webs que cambian poco: la página de una campaña, una web corporativa sencilla o un proyecto puntual.

## Lo que aporta un CMS

Cuando el contenido cambia con regularidad, la autonomía que da un gestor compensa el mantenimiento que exige:

- **Autonomía para actualizar el contenido**, sin depender de un desarrollador para cada cambio de texto, imagen o precio.
- **Un blog o una sección de noticias** fácil de mantener al día, algo poco práctico en una web estática si quien escribe no programa.
- **Extensiones** para sumar funciones, como un formulario de reservas o un segundo idioma, sin programarlas desde cero.
- **Roles y permisos de edición**, para que varias personas actualicen contenido sin acceso a la parte técnica.

Para muchas empresas, la ventaja que más pesa es sencilla: cambiar una frase o subir una foto sin pedírselo a nadie.

La contrapartida es el mantenimiento. El gestor y sus extensiones reciben actualizaciones que conviene aplicar con método, como se explica en [actualizar WordPress tú mismo o con mantenimiento profesional](/recursos/actualizar-wordpress-tu-mismo-o-con-mantenimiento-profesional/).

## Tres preguntas que lo aclaran

- **¿Cada cuánto cambia algo en tu web?** Si son unas pocas veces al año, una web estática lo absorbe sin problema. Si es cada semana, el CMS se amortiza pronto.
- **¿Quién haría esos cambios?** Si tu equipo quiere publicar por su cuenta, necesita un panel. Si prefieres delegarlo todo, la estática encaja.
- **¿Vas a publicar artículos o noticias?** Si los escribe y los publica tu propio equipo, un gestor de contenidos lo pone mucho más fácil.

Si ya tienes una web y la respuesta ha cambiado con el tiempo, el paso de una tecnología a otra se plantea como parte de un [rediseño o una evolución de la web](/recursos/redisenar-la-web-desde-cero-o-evolucionarla-poco-a-poco/).

## Cómo decidirlo

| Criterio | Web estática | Web con CMS |
|---|---|---|
| Velocidad de carga de partida | Alta | Depende de la configuración |
| Autonomía para cambiar el contenido | Pasa por quien la programó | El equipo edita desde el panel |
| Mantenimiento técnico | Mínimo | Continuo |
| Superficie de ataque | Baja | Mayor; pide actualizaciones al día |
| Blog o sección de noticias | Posible, pero cada entrada pasa por un técnico | Lo publica tu equipo desde el panel |

Una guía rápida:

- **Web estática** si el contenido apenas cambia y nadie del equipo necesita editarlo.
- **CMS** si vas a actualizar contenido a menudo, publicar artículos o repartir la edición entre varias personas.
- **CMS con [mantenimiento gestionado](/diseno-programacion-web/mantenimiento-web-para-empresas/)**, la combinación más habitual: autonomía para el contenido sin asumir la parte técnica de seguridad y actualizaciones.
